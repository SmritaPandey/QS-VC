# UPSWAN 3.0 Section 26 readiness audit

Audited 28 November 2026 against QS‑VC revision `dc8166e`, the supplied VC Compliance.pdf (printed pages 194–201), and the bidder's NeurQ_AI_VC_Compliance_Sheet.docx. Tender reference UPDESCO/UPSWAN-3.0/2026-01, tender ID 2026_UDSCL_1176931_1. The bidder sheet is a set of claims. The RFP extract is the requirements baseline. The official portal lists technical amendments, so reconcile this baseline against the complete corrigenda before using it for a submission.

**Tender readiness is blocked.** Native iOS and Android store apps are excluded from engineering scope by the user. Section 26.6 explicitly asks for them, so tender treatment still requires an applicable written exception or amended wording. Android Chrome and iOS Safari remain in the browser compatibility test scope. Section 27 is a separate mobile application and web portal specification.

## Evidence and disposition

- Regression selection ran 156 tests across 10 files for admin deployment, branding, reporting, webinar pagination, admin controls, BharatVC, permissions, and browser E2EE protocol logic. Local Chrome separately verified the previous localhost restoration and Conference Control. Those results are feature evidence with limited scope.
- [Official tender record](https://etender.up.nic.in/nicgep/app?component=%24DirectLink&page=FrontEndTendersByOrganisation&service=direct&sp=SwJvjxsPoW%2F5cGKJmvb1e1w%3D%3D) and [published technical corrigendum record](https://etender.up.nic.in/nicgep/app?component=%24DirectLink&page=Home&service=direct&session=T&sp=S2QT9b0gSZweGoFX5gSILIQ%3D%3D). The supplied extract has not been reconciled against the complete amendment PDFs.
- Source anchors include `shared/validation.ts` and `shared/meeting-invitation.cjs` for capacity, `services/meeting/src/webinars.ts` for registration, `services/signaling/src/admin-controls.ts` and `bharat-vc.ts` for control scope, and `deploy/vc-onprem/docs/14-crypto-architecture.md` for pilot crypto evidence.
- The independent technical reviewer returned BLOCK for Section 26 readiness even with store apps excluded. It identified capacity and mixed-protocol feature gaps, missing cipher/IdP/failover evidence, and site operations evidence gaps. It confirmed that the current installer runs migrations after a backup, while signed target-host upgrade and restore still require qualification.
- Bid-sheet disposition. Treat a demonstrated gap as No and an unqualified claim as pending qualification in the internal matrix. The Yes entries for capacity, live NIC integration, failover, encryption and operations cannot be substantiated with current evidence.

## Post-implementation verification

- 1,068 tests passed across 146 files after the integrated TypeScript changes. Capacity tests cover configured limits and room policy. The recording integration covers upload, playback ranges, persistence across service restart, lease revocation on restart, and denial across organisations. The bridge tests cover SDP validation and rejection of a weaker answer.
- Merged offline Compose configuration verified the setting in both meeting and signaling, and verified the persistent recording mount. Native Linux setup now explicitly applies the on-prem authentication profile and routes live-stream requests to the recording service. Target Linux runtime and volume ownership remain unverified.
- The installer operator command `qsvc doctor` probes HTTPS with hostname verification, auth and meeting readiness, signaling and SFU health, and recording configuration. It is a local probe. Branch failover and real media require an external client.
- The technical reviewer found the native deployment profile/routing omission and the SFU rate-limit constraint. The native source was then corrected and checked for shell syntax. The reviewer did not complete a final verdict on that revision. Tender readiness remains blocked by outstanding technical and site acceptance evidence.
