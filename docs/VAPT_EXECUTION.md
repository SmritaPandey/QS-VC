# QSVC staging VAPT execution record

Status: awaiting authorized targets. Keep the record with the tested release revision. Store redacted evidence in the assessment workspace.

| Authorization field | Required input |
|---|---|
| Owner and approval reference | Name, date, authorization record |
| Targets and exclusions | Exact staging URLs, IPs, tenants and explicitly excluded systems |
| Window and limits | Time zone, start/end, source IP, maximum requests and concurrency |
| Identities and fixtures | Two disposable tenants, guest/member/host/admin roles, synthetic recording |
| Methods | Burp passive/manual, explicitly approved active checks, Nessus policy and credentials |
| Emergency contact and stop criteria | On-call owner, service degradation, unexpected data exposure |

| Check | Procedure | Expected result |
|---|---|---|
| Session revocation | Capture an authenticated request in Burp Repeater. Sign out, replay the request and try a protected WebSocket operation. | Revoked session cannot access protected data or operations. |
| Tenant isolation | From tenant B, replay tenant A meeting and recording IDs across allowed read and write routes. | No cross-tenant data or state change. |
| SFU control | On the authorized staging host, request an SFU API with no bearer, an incorrect bearer, then the provisioned service credential. | First two receive 401. A valid request succeeds. Verify external port 4000 is unreachable from the approved test network. |
| Media and relay | Join from two devices, then test a restricted network with relay fallback. Exercise expired TURN credentials. | Direct and relay paths work within policy. Expired credentials cannot allocate a relay. |
| WebSocket abuse | Use synthetic rooms to send malformed, oversized and bounded bursts of messages within the approved limits. | Requests fail safely. Other rooms remain available. |
| Host and containers | Run a safe credentialed Nessus policy on the named staging host. Verify exposed services and review high-risk findings manually. | Inventory matches deployment. Confirmed findings have owners and retest evidence. |

Record tool version, revision, asset, identity, expected and observed result, redacted evidence, CWE, applicable ASVS/API/WSTG reference, CVSS version and vector, owner and retest. Use the [roadmap](QSVC_IMPLEMENTATION_ROADMAP.md) for scoring and stop rules.

## Proposed first window for owner approval

Use a 30-minute staging window in IST (UTC+05:30), with exact start and end
timestamps recorded by the owner. Start with Burp passive inspection and manual
replay using synthetic accounts. Limit all test traffic to 30 requests per minute
and one request in flight. These are proposed limits, subject to the owner's
approval and staging capacity. The repository identifies qsvcmeet.com as the
public website and backend.qsvcmeet.com as its origin. Neither is part of
this staging baseline.

Copy [the scope template](vapt-scope.example.json), fill in the approved details,
and run `node scripts/check-vapt-scope.cjs /path/to/approved-scope.json` during the
window. The check validates scope fields locally. The operator must verify the
approval reference, restrict Burp to the exact target, and enforce the rate.
Space manual requests at least two seconds apart and count browser traffic
generated by testing toward the same budget. Stop at the end of the window.

Burp active scanning and Nessus each need their own approved policy, target
and limits. For Nessus, record the specific owned host, allowed ports and checks,
and scanner concurrency settings. A web request budget does not define a
network scan policy.
