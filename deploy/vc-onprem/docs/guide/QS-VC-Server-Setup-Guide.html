Part 1 · How QS-VC works in your organisation

You install QS-VC once, on one server at your head office or data centre (the "hub"). Every branch connects to that server over your private network (for example MPLS). Meetings, recordings and user accounts stay on your server; nothing is sent to the internet.

After setup, staff open a web address such as https://vc.yourorg.gov.in in a browser, or use the QS-VC app, which your server hands out on its own /downloads page.

Who should do this

Anyone who can follow instructions carefully. You will need help from your network person twice: to give the server a fixed IP address and a name (Part 2), and to allow the network ports (Part 5). Show them those pages.

Part 3 · Download the right file

  1. On your PC, open https://qsvcmeet.com/intranet and find Install the QS-VC server.
  2. Choose Linux server setup (.run). Download it from a connected computer and transfer it to your existing Linux host using your organisation’s approved process.
  3. Keep the installer, its .sha256 file and both signature files together. Obtain the release signing key fingerprints independently. The .tar.gz download is a manual server package for IT. For this guide, use the .run file.
If a card says "Coming soon"the installer is not published yet. Contact QS-VC for a signed release.

Part 4 · Install on a Linux server (.run file)

A. Copy the file to the server

Use WinSCP, a free program for Windows (from winscp.net). On a Mac, use the scp command or a USB stick.

  1. Open WinSCP. In Host name type the server's IP address. Type the server's user name and password. Click Login.
  2. If asked about an unknown server, compare the SSH host key fingerprint with the value from your IT team before accepting it.
  3. On the left, find the downloaded file (usually in Downloads). Drag it to the right-hand side (your home folder on the server). Wait for the copy to finish.
No network yet?Copy the file onto a USB stick, plug it into the server, and copy it from there. Your IT person can help with mounting the stick.

B. Open a command window on the server

  1. Either sit at the server's own screen and keyboard and log in, or connect from your PC with PuTTY (free, from putty.org): type the IP address, click Open, then log in.
  2. You now see a line ending in $ or #. This is where you type commands. Press Enter after each one.

C. Check the file and start the installer

  1. Go to the folder that holds the file. If you copied it to your home folder, type: cd ~
  2. Check that the file arrived complete. Type: sha256sum ./qsvc-server-setup-VERSION.run Replace VERSION with the version in your downloaded filename. Compare the long code shown with the SHA-256 on the download page. They must be exactly the same. If not, download and copy the file again.
  3. Start the installer. Type: sudo bash ./qsvc-server-setup-VERSION.run If asked for a password, type your own login password (nothing appears while you type; that is normal) and press Enter.
Moving around the installer screensUse the arrow keys to move, Tab to jump to the buttons, and Enter to press a button. The mouse does not work in these screens.

D. Answer the installer screens

For unattended installation, copy the release’s answers.example.env into a root-only answers file. Fill in the exposure, hostname, IP, certificate choice, admin details and independently verified fingerprints. Protect the answers and admin password files with mode 0600. Start it with:

sudo bash ./qsvc-server-setup-VERSION.run -- --silent --answers /root/qsvc-answers.env
  1. Licence agreement. Read it (arrow keys to scroll), press Enter, then choose Yes to accept.
  2. Fingerprints. The screen shows two codes:
    QS-VC Server Setup
    Compare these release key fingerprints with the ones QS-VC sent you separately:

      Ed25519    3fa1…    ML-DSA-65  9c0e…

    Do the fingerprints match? <Yes> <No>

    Compare them with your worksheet. If they match, choose Yes. If they do not match, choose No and contact QS-VC: the file may have been changed.
  3. Checks run by themselves. The installer checks the file's signatures and the server (processor, memory, disk, ports, clock). Lines with a green tick are fine. If it stops with a red message, see Part 9.
  4. Access profile. Choose Intranet or organisation VPN for private access, or Intranet and internet via the organisation edge if remote staff will connect directly. IT must prepare external DNS, HTTPS and media forwarding for the second option.
  5. Organisation name. Type it and press Enter.
  6. Server name. Type the name from your worksheet (e.g. vc.yourorg.gov.in).
  7. Server IP address. The installer suggests one. Check it matches your worksheet; correct it if needed.
  8. First administrator email, then the password twice.
  9. Server certificate. For internet access, select your organisation’s certificate and supply the trusted certificate chain and matching key. For intranet-only use, you can choose the QS-VC internal CA. If IT gave you a private CA bundle, supply its path when prompted.
  10. Wait. The installer now loads QS-VC and starts it. This takes 10 to 20 minutes. Do not close the window.

Part 5 · Connect your network and computers

A. Ask your network person to do two things

  1. DNS: make the server name (e.g. vc.yourorg.gov.in) point to the server's IP address, for all branches.
  2. Firewall: allow these from every branch network to the server:
    TypePortsUsed for
    TCP80, 443Website, sign-in, app downloads
    TCP and UDP3478Connecting calls through firewalls
    UDP40000–40100 and 49152–49200Audio and video
    Have IT confirm host firewall rules. The internet profile leaves existing host rules in place by default. External users need the approved HTTPS/WebSocket and media paths via the organisation edge.

B. Trust the server's certificate (only if you chose "internal")

Without this step, browsers show a "Not secure" warning. Do it once per computer, or let IT push it to all PCs with Group Policy.

  1. Ask IT for the verified QS-VC-Root-CA.crt from the server console. IT can export it with sudo qsvc ca and distribute it through the organisation’s trusted device management process.
  2. Windows: double-click the file → Install Certificate → Local Machine → Place all certificates in the following store → Browse → Trusted Root Certification Authorities → Next → Finish.
  3. Mac: double-click the file → it opens Keychain Access in System → double-click "QS-VC" → open Trust → "When using this certificate": Always Trust → close and enter your Mac password.
  4. Group Policy (many PCs): IT imports the file in Computer Configuration → Policies → Windows Settings → Security Settings → Public Key Policies → Trusted Root Certification Authorities.
  5. Close and reopen the browser. Open https://your-server-name: the warning is gone.

C. Sign in for the first time

  1. Open https://your-server-name in Chrome, Edge, Firefox or Safari.
  2. Sign in with the administrator email and password you chose during setup.
  3. On the server, run sudo qsvc status and sudo qsvc doctor. Pass the organisation CA file to qsvc doctor if the private issuer is absent from the server trust store. In the browser, choose New meeting and send the invitation to a second authorised user. Confirm they can join and that both users can hear and see each other. Share a test screen and end the meeting.

D. Check guest screen sharing

  1. Open the organisation’s trusted HTTPS address in a supported desktop browser. Join from a second browser session as a guest and have the host admit you.
  2. Admitted participants can share by default in new meetings. If the meeting has sharing turned off, the host can enable Share their screen under More → Host controls → Let everyone. In a webinar, invite audience members on stage before they share.
  3. As guest, open the screen sharing control and choose a source. Use Entire screen to present across apps, or choose a specific Window or Browser tab to limit what viewers can see.
  4. Have the other participant confirm the share continues when you switch apps. Stop sharing and confirm the presentation disappears.

If sharing is unavailable, confirm the host grant, the trusted HTTPS address and system screen recording permission. Turn off Audio-only under More → Connection quality. Try sharing without optional source audio if sound fails.

Part 6 · Connect staff devices

Give staff the organisation’s HTTPS meeting address. On Windows, Mac and Linux, open it in a supported desktop browser. On iPhone and iPad, open it in Safari. On Android, open it in Chrome. Use the invitation or sign in and open Meetings. Allow camera and microphone only when you want to use them. Native iOS and Android apps are outside this release.

Before rollout, run the meeting check in Part 5 on each device family you support. For internet access, repeat from a device outside the organisation network. Test screen sharing on desktop. For existing room equipment, ask IT to verify an authorised Bharat VC or Polycom call separately.

Optional desktop downloads

Staff can join from a browser, but the QS-VC app is easier for daily use. Your server shares it on https://your-server-name/downloads/.

A. Put the app files on the server (administrator, once)

  1. Get the QS-VC app installers from QS-VC: Windows (QS-VC-Setup-…-x64.exe), Mac (QS-VC-…-macOS-arm64.dmg for Apple chips, …-x64.dmg for Intel) and Linux (.deb, .rpm).
  2. Copy them to the server with WinSCP (as in Part 4A) into your home folder.
  3. On the server, type: sudo cp ~/QS-VC* ~/qs-vc* /opt/qsvc/downloads/ 2>/dev/null; sudo chmod 644 /opt/qsvc/downloads/*
  4. Open https://your-server-name/downloads/: the files are listed.

B. Install the app on a staff computer

ComputerSteps
WindowsDownload the .exe from the downloads page → double-click → if "Windows protected your PC" appears, More info → Run anyway → Next → Install → Finish.
MacDownload the .dmg (Apple chip = arm64, Intel = x64) → open it → drag QS-VC to Applications. The first time, right-click QS-VC → Open → Open.
LinuxUbuntu: sudo apt install ./qs-vc_*_amd64.deb. Rocky/RHEL: sudo dnf install ./qs-vc-*.x86_64.rpm.

When the app opens the first time, it asks for your organisation address. Type https://your-server-name and sign in.

For IT: install on many Windows PCs at onceThe Windows installer can run silently and pre-fill the address for everyone: QS-VC-Setup-1.1.0-x64.exe /S /SERVERURL=https://vc.yourorg.gov.in Use this with Intune, SCCM or a login script.

Part 7 · Activate QS-VC (before the 14 days end)

QS-VC works fully for 14 days after installation. To keep using it, QS-VC approves your installation. If the 14 days pass first, users see "This QS-VC installation needs activation". Nothing is deleted; everything returns as soon as you activate.

  1. Find your Installation ID (it was on the Congratulations screen). Or type on the server: sudo qsvc status
  2. On https://qsvcmeet.com, use Contact us. Send the Installation ID and your organisation's account email.
  3. QS-VC sends you a file named qsvc-onprem-license.json. Copy it to your home folder on the server (WinSCP, as in Part 4A).
  4. On the server, type these two lines: sudo install -m 0644 ~/qsvc-onprem-license.json /var/lib/qsvc/onprem-trial/license.json.new sudo mv /var/lib/qsvc/onprem-trial/license.json.new /var/lib/qsvc/onprem-trial/license.json
  5. Reload the QS-VC page in your browser. It works again. If it does not within a minute, type sudo qsvc restart.

QS-VC starts automatically when the server restarts. You do not need to do anything after a reboot.

Who can see administration data?

Organisation meeting views are scoped to the signed-in organisation. A platform administrator can see platform-wide summaries for the installation they manage. Hosted and self-hosted installations have separate data. If your intranet and internet entry points use the same installation, they share that installation’s data. Hosted accounting has no automatic feed from an isolated server.

Organisation services and recording

Copy /etc/qsvc/compose.organisation.example.yml to /etc/qsvc/compose.organisation.yml only when adding site-specific integration. Keep it root-only. Use the approved identity broker for SSO, and a separately provisioned gateway for Polycom or Bharat VC. Restart QS-VC and verify from a branch client.

The offline installer stores uploaded recordings on a persistent local volume. Use encrypted storage and include the volume in your backup and restore checks. Keep the database, settings and recording backups together for recovery.

Update to a new version

Obtain the versioned installer, its checksum, and both checksum signatures. On the server run sudo qsvc check-update ./qsvc-server-setup-VERSION.run. Schedule downtime, drain meetings and take a recoverable backup before running the installer on the same Linux host. Afterward, run sudo qsvc doctor and verify sign-in and a two-user call. After a failed migration, review the setup log. Restore the coordinated backup if schema changes prevent a safe version rollback.

Part 9 · If something goes wrong

You seeWhat to do
"run as root (sudo)"Start the installer with sudo in front, as in Part 4 step 5.
"this package is for x86-64 servers"The server has an ARM processor. Use an Intel/AMD server or virtual machine.
"release key fingerprints not confirmed"The codes did not match, or you chose No. Download the file again from qsvcmeet.com; if they still differ, contact QS-VC and do not install.
"signature or file check failed"The file is damaged or changed. Download and copy it again. Do not install it.
"memory … is below the 8 GB minimum"Give the server more memory (16 GB recommended).
"only … GB free" (disk)Free up or add disk space (30 GB minimum, 100 GB recommended).
"port 80/443/3478 is already in use"Another program (often a web server) is using it. Ask IT to stop it, or use a server dedicated to QS-VC.
"Clock is not NTP-synchronised"Set the correct time and a time server; wrong time breaks sign-in.
"Podman is not installed and your package repository could not provide it"New Linux server installations use Podman; Docker is not required. On Rocky/RHEL ask IT to run sudo dnf install podman; on Ubuntu sudo apt install podman. Then run the installer again.
"invalid server name" / "invalid IPv4 address"Check spelling: a name like vc.yourorg.gov.in (no https://) and an address like 10.20.1.50.
"the certificate is not issued for …"Your organisation's certificate is for a different name. Get a matching one, or choose "internal".
"… is not healthy"Check sudo qsvc status and sudo qsvc logs. For an upgrade failure, review the setup log before retrying. If the cause is unclear, send a support bundle (sudo qsvc support-bundle) to QS-VC.
Browser says "Not secure"Do Part 5B on that computer.
Branches cannot open the addressCheck Part 5A with your network person (DNS and firewall).
Video freezes or there is no sound between branchesThe UDP ports in Part 5A are blocked somewhere on the network.
"This QS-VC installation needs activation"The 14 days have passed. Do Part 7.

Getting help

Contact QS-VC through Contact us on qsvcmeet.com (or support@qsvcmeet.com). Include your Installation ID and attach the support bundle: the command sudo qsvc support-bundle tells you where it saved the file. The full setup log is at /var/log/qsvc-setup.log.
